## Routing and static pages

Every page is a real file, so direct visits and refreshes work on plain Apache with no rewrite rules:

```
dist/
  index.html                  home
  image-converter/index.html  one folder per visible tool
  credits/index.html
  404.html                    served by Apache's ErrorDocument
  sitemap.xml  robots.txt
  assets/                     hashed JS, CSS, fonts, worker chunks, qpdf WASM
  vendor/pdfjs/               pdf.js data files (cmaps, standard_fonts, iccs, wasm)
```

`scripts/static-routes.ts` runs after the build. It copies the built `index.html` once per route and swaps in that page's title, description, canonical URL and Open Graph tags (escaped). `404.html` is `noindex` with no canonical. The sitemap lists the home page, visible tools and static pages only. Every page loads the same bundle, and the client picks the view from `location.pathname`.

Apache behaviour (mirrored by `scripts/serve-dist.mjs` in e2e):

- `/image-converter/` → `image-converter/index.html`.
- `/image-converter` → 301 to `/image-converter/` (`mod_dir`).
- Unknown paths and hidden tools → `404.html` with status 404.

## Tool processing

1. The file picker reads a local `File` ("Choose file" or drag and drop). Nothing is uploaded.
2. Heavy work runs in a module Web Worker via `runWorker`. Cancel terminates the worker. Progress comes back as `{type: "progress"}` messages.
3. When a browser lacks what the worker needs (for example `OffscreenCanvas` in some WebKit builds), the tool runs the same code on the page via `runCancellable`. Cancel drops the late result (D30).
4. Output is a `Blob`. It is downloaded through a temporary object URL, revoked afterwards. Preview URLs are revoked on reset or unmount.

### PDF tools

- **Engines.** pdf-lib edits structure (pages, text, images, metadata, forms). pdf.js (legacy build) renders pages and reads text. qpdf (WASM) encrypts and decrypts with AES-256. Each runs only in the browser.
- **Worker.** `runPdf` starts a fresh module worker (`pdf.worker.ts`) per job and transfers the input buffers to it, so no copy stays on the page. Cancel terminates the worker. Compress needs `OffscreenCanvas` to re-encode JPEGs; without it, that one operation runs on the page.
- **Rendering.** pdf.js parses in its own worker. Pages render on demand (IntersectionObserver queue) and canvases are capped at 16 megapixels. Documents are destroyed on reset.
- **pdf.js hardening.** All data files come from `/vendor/pdfjs/` on our origin. No scripting, annotation or form layers, XFA off, no streaming or range requests. Password prompts are refused (the file is reported as encrypted).
- **Limits.** Files over 1 GB are refused before reading. Inputs must start with `%PDF-`. Malformed files map to clear messages (`core/errors.ts`).
- **Fidelity.** No tool rasterises pages unless it says so (PDF to JPG/PNG). Compress only re-encodes large JPEG photos and keeps the original when the result is not smaller.

## Constraints

- **Static only.** The output is `dist/` from `vite build`, and its contents are uploaded to `public_html/`. No server code at runtime.
- **Client-side processing.** All file work happens in the browser on the user's CPU, GPU and RAM.
- **No egress of user data.** The only network requests are for our own static assets (JS, CSS, WASM, models, fonts), plus approved analytics events if enabled.
- **Single maintainer.** Few, well-maintained dependencies and a flat structure.

## Hosting

| Layer | Detail |
|---|---|
| Server | Ubuntu VPS, Virtualmin, Apache (static files only) |
| DNS / edge | Cloudflare, HTTPS |
| Docroot | `public_html/` ← contents of `dist/` |
| Server config | `.htaccess` shipped in `dist/` (from `public/`) |

`.htaccess` responsibilities:

- `ErrorDocument 404 /404.html`, `DirectoryIndex index.html`, `Options -Indexes`. No SPA fallback is needed, because every route is a real file.
- MIME types for `.wasm`, `.mjs`, `.webmanifest`
- Long cache for hashed assets, no-cache for `index.html`
- COOP/COEP (`Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Embedder-Policy: require-corp`) for `SharedArrayBuffer` (multi-threaded ffmpeg.wasm and ONNX). This needs `mod_headers`.
- CSP and security headers (Phase 09)

Cloudflare notes: make sure it passes the COOP/COEP/CSP headers through. Turn off script-injecting features (Rocket Loader, auto Web Analytics, Zaraz, email obfuscation). Watch the 100 MB per-file upload and cache limits for large models.

### Principles

1. **Lazy load per tool.** A tool's WASM or model loads only when it is opened.
2. **Workers for heavy work.** Data moves via `postMessage` and transferables, never storage.
3. **The registry gates visibility.** Only enabled, `status: "verified"` tools appear in navigation, search, routes and the sitemap.
4. **Self-host everything.** No third-party CDN at runtime.
5. **Output = download.** Blob/object URLs are revoked after use.
6. **Analytics adapter is a no-op by default.** A single module, with the event enum defined in `PRIVACY.md`.
